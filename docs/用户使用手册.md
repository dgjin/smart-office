# SmartOffice 用户使用手册

- 文档版本：v1.0
- 基线日期：2026-11-25
- 适用对象：员工、参会人、审批人、会务/前台、系统管理员、保密管理员

## 1. 系统简介

SmartOffice 用于企业会议室和空间资源管理，覆盖找会议室、正式预约、长期预约、审批、会务服务、签到、实际使用、异常处理、运营报表、总部 3D 空间、实时监控大屏和智能助手。

使用时请注意：

- 页面菜单会按当前身份和实际职责显示。
- 新建、修改和续期预约必须在正式表单中核对并提交。
- 助手可以查询、指导、导航和预填，但不能绕过审批、涉密控制或最终确认。
- 涉密会议的用途和人员信息只向授权人员展示。
- 企业外部消息、OA、日历、门禁等适配器是否可用，以企业实际启用和联调结果为准。

## 2. 登录与界面导航

### 2.1 登录

1. 打开企业提供的 SmartOffice 地址。
2. 按页面提示进入企业统一认证。
3. 认证成功后进入会议工作台。

外部身份必须事先绑定到系统已有成员。若提示认证配置或身份绑定问题，请联系系统管理员，不要反复尝试其他账号。

### 2.2 桌面和移动端

- 桌面左侧为固定功能导航，右侧内容独立滚动；切换主视图时自动回到内容顶部，避免保留上一页的滚动位置。
- 桌面侧栏可以收起；进入总部 3D 时会为画面临时让出宽度。
- 移动端主要功能位于底部导航，其余功能从“更多”进入。
- 桌面在侧栏底部“界面风格”选择主题；“东方蓝”采用白色品牌侧栏、东方蓝选中导航和深蓝标题，也可随时切回商务蓝、翡翠绿等原主题。所有主题统一使用中国东方横式组合标志：东方蓝使用蓝色稿，其他五套主题使用透明反白稿；侧栏收起后保留中国东方图形标，展开后恢复完整横式标志。
- 移动端从“更多 → 界面主题”选择同一套主题。选择东方蓝后，总部楼层 3D 与空间资源库内的 3D 剖切同步使用白色面板、东方蓝选中态和深海蓝模型背景；切回原五套主题后保留经典 3D 配色，所有主题均显示相同的中国东方横式标志。主题和侧栏偏好保存到 MySQL，刷新、重新登录或服务重启后恢复；主题切换不改变空间状态、资源、预约数据、权限和操作流程。

### 2.3 帮助入口

- 顶部栏的 **打开帮助**：查看当前身份可用的功能指南和智能帮助；窄屏显示帮助图标，功能不变。
- 右下角的 **打开智能助手**：进入对话式办公助手。

## 3. 会议工作台

会议工作台用于快速了解今日安排、个人待办和空间使用情况。可查看：

- 今日、本周、本月的相关安排和指标卡片。
- 今日资源时间分布、即将开始的会议和通知。
- 当前角色需要的审批、会务或异常事项。
- 常用功能入口和空间资源概览。

点击具体预约或资源可进入对应详情。主动展开涉密预约详情时，系统会重新检查读取权限并记录读取审计；工作区自动刷新不会产生这类详情审计。定向通知与系统广播均按当前用户显示已读状态，一名用户读取广播不会改变其他用户的未读状态。数据刷新失败时，以页面错误提示为准，不要把旧数据当成最新结果。

### 3.1 会议室与办公室监控

会议室监控和办公室监控是两个独立页面，访问权限也分别配置。系统管理员默认允许查看；其他用户须由管理员在“系统管理 → 权限集管理”中编辑角色，分别勾选“会议室监控”或“办公室监控”。未授权用户不显示入口，直接打开链接、使用智能助手或请求接口也不能查看。

获授权后，桌面分别点击左侧“会议室监控”或“办公室监控”，移动端从“更多”选择对应入口。可复制链接分别为 `#/monitoring/meeting-rooms` 和 `#/monitoring/offices`，刷新及浏览器前进后退可恢复页面。

**会议室实时使用**

1. 查看“实时推送已连接”和最近更新时间，确认当前快照状态。
2. 通过指标和状态筛选查看已签到使用中、预约占用、当前空闲、维护中和待开放房间；五种状态分别使用红、蓝、绿、琥珀、灰色，房间标题区显示对应浅底色，实心徽标同时提供语义图标和文字，具体状态以文字为准。
3. 房间卡片显示当前会议时段、可见签到信息和下一场已核准安排；待审批申请不计为当前占用，提前结束或释放后会自动更新。
4. 涉密会议按当前用户权限展示，未授权人员只能看到“已预约”等占用信息，不能看到真实主题或签到详情。

**办公室使用情况**

1. 查看已分配、空置、未登记和维护中汇总，分别使用蓝、绿、灰、琥珀色，并同时显示语义图标和文字；点击汇总卡可按状态筛选。
2. 组合使用楼栋、楼层和关键词筛选；关键词可匹配房间、部门或使用人。
3. 记录较多时点击“显示更多”；窄屏下左右滚动办公室表格查看完整列。

办公室数据来自总部 3D 当前房间资料和维护记录。“已分配”只表示登记了使用人或部门，**不代表门禁、传感器或现场实测有人**。实时监控采用 SSE 推送，普通网络断连时保留最近一次成功快照并自动重连；角色权限被撤销时连接会停止、旧受控数据会清除，需要联系管理员核对授权。连接中断或数据暂时不可用时，不要把旧快照当成当前事实。正式统计和导出仍使用运营报表。

## 4. 查找空间与预约会议室

### 4.1 按条件查找

1. 打开“空间资源库”。
2. 选择日期、开始和结束时间。
3. 按需填写人数、资源类型、楼栋、楼层、会议室类型和设备条件。
4. 查看符合条件的资源、房间名录、周历和空间导航。
5. 点击目标资源的“预约”。

筛选条件会与空间导航联动。总部 3D 剖切只显示已建立显式映射的业务状态，未映射房间不会被系统自动当成可订资源。

### 4.2 填写正式预约

1. 核对资源、日期和时间。
2. 填写真实、具体的申请用途和参与人数。
3. 选择会议类型和涉密确认，两项必须一致。
4. 按需选择参会人、领导、视频、茶水、车辆、礼堂布置等服务。
5. 核对申请人姓名、座机和手机；联系人档案不完整时先联系管理员维护。
6. 查看冲突、开放时段、参会人提醒和部门额度提示。
7. 点击“确认预约”。

提交后系统会重新检查资源冲突、申请人冲突、容量、设备、部门额度和审批规则。页面显示提交成功只代表申请已受理，是否可用以最终审批状态为准。

### 4.3 特殊资源注意事项

- **PENDING 或维护资源**：不能按正常可订资源提交。
- **专属资源**：需满足领导条件、申请开放时间窗，并填写申请理由。
- **礼堂**：需选择座位布局、是否使用舞台，按需填写彩排时间和备注。
- **涉密会议**：申请人和全部参会人必须在保密白名单内。
- **重服务或长期申请**：可能进入额外审批节点。

### 4.4 周期与长期预约

1. 在预约表单选择周期或长期方式。
2. 设置重复规则和截止日期，长期范围不能超过系统允许的一个月窗口。
3. 核对系统拆分的各次日期、开放时段、冲突和部门日额度。
4. 提交后按系列查看审批状态。

超过当前长期窗口需要继续使用时应申请续期，不要通过重复新建绕过审批。

## 5. 我的申请与会议使用

### 5.1 查看和筛选

打开“我的申请”，可按状态、时间和关键词找到本人预约。列表会区分待审批、即将开始、进行中、已完成、已取消、已驳回、未签到释放和提前结束等展示状态。

### 5.2 修改预约

1. 打开本人仍处于可修改状态的预约。
2. 点击“修改”。
3. 调整时间、用途、人数、参会人或会务需求。
4. 核对后重新提交并等待所需审批。

修改时间会产生新的排期版本，旧提醒和自动任务不再作用于新时间。涉密预约按专门权限和变更流程处理，不能通过普通助手草案绕过。已核准涉密预约需要变更参会人时，须先取得匹配的一次性授权，提交后重新进入审批；授权不能由申请人给自己签发。

### 5.3 取消预约

1. 打开本人可取消的预约。
2. 点击“取消”，按需填写原因。
3. 在确认提示中最终确认。

取消会联动未完成服务和相关授权。若资源已被异常释放或状态已变化，以服务端最新结果为准。

### 5.4 长期预约续期

1. 打开已核准的长期系列首条预约。
2. 点击“续期”。
3. 核对新的续期范围和每次安排。
4. 提交并等待审批。

存在待审批或活跃续期时不能重复申请。打开续期表单不等于续期成功。

### 5.5 签到、使用确认与结束

- 申请人和参会人均可在“计划开始前 15 分钟（含）至计划结束时间（不含）”内签到或确认实际使用；会议结束后不能再补做普通签到或使用确认。
- 确认“未使用”必须填写说明，并复用取消预约的授权检查；无取消权限时不能通过使用确认释放预约。
- 已签到的已核准会议在计划结束时间由系统自动正常结算为“已完成”，实际结束时间记录为计划结束时间，不需要人工补做结束操作。
- 需要提前释放资源时，在预约详情选择“提前结束”并确认；实际结束按本次操作时间记录，部门日额度也按实际结束重算。正常完成仍按计划时段计算额度。
- 正常完成、提前结束、no-show 和确认未使用分别进入运营对账；仅本人因 no-show、确认未使用或人工异常而释放的预约可以发起使用申诉，主动取消不属于可申诉异常。
- 恢复前系统重新检查时间、资源与申请人冲突、部门额度和涉密白名单。原申请无需审批时，恢复后可直接核准并重建会务与提醒任务；原申请有冻结审批流程时，恢复后从首节点重新审批，审批通过前不会提前生成新工单。

### 5.6 导出日历

在支持的预约详情中下载 ICS 文件，再导入个人日历。已核准预约导出为 confirmed，取消预约导出为 cancelled；ICS 下载不等于企业日历平台已完成联调。

## 6. 审批中心

适用于具有当前节点审批职责或有效代理职责的用户。

1. 打开“审批中心”。
2. 查看待审批申请、用途、资源、时间、参会人、服务和规则说明。
3. 打开详情核对冲突、长期系列、涉密或专属要求。
4. 选择“同意”或“驳回”，按需填写意见并确认。
5. 需要时使用批量审批，但仍应逐项核对适用范围。

审批结果以服务端当前节点和权限重检为准。代理人只能在有效代理期和授权范围内处理，不能借代理绕过自审限制。

## 7. 会务工单与异常中心

### 7.1 处理工单

适用于服务协调、前台、审批管理员、系统管理员及实际工单负责角色。

1. 打开“会务工单”。
2. 按状态、服务类型、时间或预约筛选。
3. 查看预约时冻结的服务目录版本、字段和 SLA。
4. 根据实际情况切换待办、待补充、进行中、已完成或异常状态。
5. 填写处理说明和实际成本，保存后核对状态历史。

历史目录不会因后续目录修改而自动变化。取消或释放预约后，未完成服务会按规则联动。默认责任区只包含尚未分配到自定义责任区的会议室；按资源、公司和楼栋均未匹配时，最终由 `area-default` 兜底。

涉密会议的服务责任人和巡查责任人可以凭自己负责的工单或巡查完成履约，但只能看到服务执行所需信息，会议主题、申请人、参会人和联系人仍保持隐藏。该权限不能用于查看完整涉密预约，也不开放给无关会务角色。

### 7.2 异常中心

用于处理未签到释放、使用事实缺口、签到事实缺口、服务异常和其他需要人工介入的事项。

- 先核对预约、当前排期版本、签到事件和实际使用事实。
- 人工释放或恢复必须填写真实原因并确认权限；主动取消不能通过申诉恢复。
- 需审批的预约恢复后会回到首节点重新审批，原审批历史不直接沿用；自动核准预约恢复后才立即重建工单和提醒。
- 处理结果会进入通知、审计和运营对账。
- 不要把“暂无异常”当成外部设备或企业平台已联调的证明。

## 8. 总部楼层 3D

### 8.1 浏览空间

1. 打开“总部楼层 3D”。
2. 切换主楼或南配楼、楼层和视图模式。
3. 点击房间查看房号、名称、功能、使用人、面积和维护状态。
4. 使用房间清单和空置页签定位空间。

系统包含主楼 20 层和南配楼 4 层。面积未登记时显示“—”，不会自动编造数值。主楼 2F 礼堂在 3D 中显示主席台、主席桌椅、讲台和面向主席台的观众席；座位按房间可用宽深比例排布，并保留台前通道、中央过道和侧向边距。移动端单层模型会自动完整显示在底部功能抽屉上方，可继续缩放或选择房间。该视觉排布不代表已核定业务容量，实际预约人数仍以资源台账为准。

### 8.2 资料和维护

具有系统管理员、服务协调或前台角色的用户可按页面能力：

- 修改房间资料并查看变更历史。
- 创建和推进维护报修。
- 维护楼层面积合计。
- 在资源库和 3D 之间查看显式映射结果。

未核定 UID、PENDING 容量和候选可订空间需管理员在 UAT 中继续确认，不能仅凭 3D 中可见就直接预约。

### 8.3 导入文件更新楼层图

仅系统管理员可在完整“总部楼层 3D”页面使用该功能，空间资源库内嵌剖切不显示布局导入入口。支持 `.json`、`.xlsx`、`.png`、`.jpg` 和 `.jpeg`，所有格式都必须经过预检和人工确认，Excel 或图片识别不会直接写库。

1. 点击“导入文件更新楼层图”，选择“整栋”或“单层”，再选择目标楼栋；单层模式还需选择目标楼层。
2. 精确更新可点击“导出 JSON 模板”或“导出 Excel 模板”。保留格式、版本、范围和既有房间 UID，只修改需要调整的房间资料、名称或 `nx/nz/nw/nd/frac` 归一化几何。
3. 选择修改后的 JSON、系统 Excel 模板或原生楼层图 Excel，或选择目标单层的 PNG/JPEG 图片，点击“预检布局变更”。核对新增、修改、恢复、停用、不变数量、识别提示和错误列表；预检只读，不会更新布局。
4. 原生楼层图识别结果会列出识别楼层、空间及未匹配既有 UID 数量。核对重复楼层版本选择、房间文字、类别和换算坐标；封皮、未选版本及打印区域外内容不会进入布局。
5. 图片识别结果中会列出匹配现有、新增候选和保留未识别房间数量。既有房号对应的部门、人员等多行文字变化会进入“修改”差异，原 UID、类别、维护备注和几何保持不变；新增房间名称、识别误字与估算坐标必须逐项人工核对，识别质量不足时请改用 Excel，不要直接确认。
6. 预检通过且存在实际变化时，点击“确认导入”。成功后页面自动刷新；预检后如布局已被其他操作改变，系统会拒绝过期确认，请重新导出或预检最新布局。

系统 Excel 模板包含“布局信息”“楼层”“房间”“填写说明”四张工作表：

- “布局信息”记录格式、版本、范围、楼栋与比例；“楼层”独立声明楼层，因此空房间楼层也能保留；“房间”记录 UID、房号、类别、名称、部门、人员、备注、标签行和完整归一化几何。
- 不要修改工作表名称、表头或公式。标签行使用单元格内换行分隔；房间所属楼层必须已在“楼层”表声明。

原生楼层图 Excel 按本次附件结构识别：

- 工作表按“楼栋 + 中文楼层 + 可选版本”匹配，例如“主楼一层”“主楼二层（全）”。整栋读取当前全部楼层，单层只读取所选目标楼层；封皮和其他楼栋工作表不参与更新。
- 房间以打印区域内的合并单元格或独立单元格为边界，标题行、合并从属单元格和打印区域外杂值会被过滤；没有打印区域时按有效房间标注推导边界。横向按列宽、纵向按行高换算 `nx/nz/nw/nd`，面积占比按识别区域归一化。
- 二层同时存在“全/部分”时优先“全”，十四层同时存在“新/旧”时优先“新”；识别提示会列出实际选用版本。相同最高优先级存在多个版本时拒绝导入，请先整理文件。
- 系统按房号、名称和位置匹配既有房间并沿用稳定 UID；未匹配项生成新 UID。识别后的文字、类别和坐标必须人工核对，新空间不自动成为可预约资源。
- 支持的是附件所示的楼栋、中文楼层工作表及单元格绘制结构，不代表兼容任意外部 Excel；结构不符时请改用系统 Excel 模板。

图片识别与精确更新的差异：

- 图片只支持单层，使用本地中文 OCR，不上传到第三方识别服务。房号、部门、人员和括号说明可位于同一行或上下相邻，黄色等高亮背景也可参与识别；识别结果只生成标准布局候选，OCR 误字仍须人工核对。
- 房号或明确名称匹配到现有房间时，保留原 UID、类别、维护备注和几何；房号匹配后的多行文字变化会进入预检，只有空格、换行或括号等格式差异不会制造更新。未被图片识别的现有房间自动保留，绝不因漏识别而批量停用。
- 识别出的新房间可追加，类别默认为 `meeting`，坐标仅按文字位置估算，不代表墙体边界；新房间仍需在预检中核对。
- JSON、系统 Excel 模板和原生楼层图 Excel 都是完整、精确更新：省略未映射房间会进入停用差异；这与图片的“未识别即保留”语义不同。

共同范围和保护规则：

- 整栋文件必须包含该楼栋当前全部楼层；单层文件只能包含一个目标楼层，且不能修改楼栋级名称、宽高比或全楼比例参数。首版不新增、删除或重排楼层。
- 整栋更新只影响目标楼栋，单层更新只影响目标楼层。单层文件不能把其他楼层或楼栋的房间 UID 移入；整栋文件可在同栋既有楼层之间移动 UID。
- 已绑定资源的房间不能通过从 JSON/Excel 中省略而停用。其他省略房间仅软停用，房间资料、维护记录、资源映射和历史保留；重新加入原 UID 可恢复该房间。
- 新布局房间只进入 3D 空间台账，不自动创建可预约资源；需要在资源库另行建档并确认显式映射。
- JSON、Excel、图片分别不能超过 2、4、8 MiB；图片还不能超过 2400 万像素或单边 10000 像素。文件结构、真实格式、几何、UID、范围及映射保护错误会以中文说明，失败不会提交部分修改。

## 10. 系统管理

### 10.1 资源管理

系统管理员可维护资源基本信息、所属公司、容量、设备、楼栋楼层、开放状态和服务能力。

1. 打开“空间资源库”的管理区域。
2. 找到目标资源，默认状态为锁定。
3. 先解锁该资源，再选择编辑或删除。
4. 在“所属公司”中填写资源台账公司；流程配置的“资源公司范围”使用同一公司值，留空表示全部公司，多个公司用逗号分隔。
5. 批量导入时继续使用原 CSV 列顺序，公司位于“公共资源”之后、“设备”之前；旧模板中的同列数据仍可解析。
6. 修改后核对预约和 3D 联动结果。

新申请按提交时的资源所属公司冻结审批范围，在途申请继续使用历史快照，不因后续资源或流程修改而改变。删除存在有效预约或设备依赖的资源会被拒绝。锁只是防止误编辑，不替代服务端权限和关联检查。

### 10.2 成员、部门与角色

- 成员档案维护姓名、部门、联系方式和完整多角色集合；编辑保存时保留该成员全部已配置角色，不只保留当前界面看到的单个职责。
- 部门支持组织层级和受控批量维护。
- 组织同步先查看 preview 差异，再由授权管理员 apply。
- 角色用于分配系统职责，具体数据权限还受审批范围、部门、公司和工单负责关系约束。

### 10.3 审批流程和规则

系统管理员可在“系统管理 → 流程配置”维护动态审批规则、节点和代理。

1. 在流程节点区域维护节点顺序、负责角色、部门和资源公司范围；代理按有效时间段配置。
2. 在动态规则集中新增、编辑或删除规则。每条规则至少设置一项条件，可组合会议类型、专属资源、重服务和连续超过天数；同一规则内的条件须同时满足，系统按优先级从高到低命中第一条规则。规则标识和优先级在同一版本内不能重复，目标流程必须真实存在。
3. 新增或编辑后点击“保存到草稿”。删除规则和调整默认流程版本同样只改变当前浏览器的编辑草稿，不会立即影响业务；需要撤销时点击“重置草稿”。
4. 核对后点击“发布新版本”并确认。系统只追加新版本并记录审计，不改写历史版本；完全无变化时不能重复发布。如果其他管理员已先发布，页面会提示版本冲突，请刷新并重新核对草稿，不覆盖对方版本。
5. 新申请使用最新发布版本；已提交预约继续使用申请时冻结的规则和流程，后续发布不会悄然改变在途审批。
6. 普通预约未命中特殊规则时仍自动核准；“默认流程版本”用于规则集版本追踪，不表示所有普通预约都会进入该流程。

### 10.4 保密管理

系统管理员或保密管理员可维护白名单和变更授权。待审批和已核准涉密预约均可按页面规则签发一次性参会变更授权；已核准预约变更后重新审批。降级仍需两名不同授权人，申请人不能给自己授权，匹配变更成功后授权自动核销。系统管理员身份本身不自动获得涉密详情读取或直接写操作权限。该功能只通过正式页面操作，助手可以提供指南和导航，但不会直接修改白名单或授权。

### 10.5 设备与数据中心

- 门口屏设备管理用于登记、状态和受控维护。
- 设备快照和心跳使用独立设备令牌边界，令牌不能出现在聊天、文档或报告中。
- 数据中心提供审计、集成对账、补偿、重放和备份恢复等高影响功能。
- 组织同步 apply、集成补偿/重放、设备撤销/重启和备份恢复必须由授权人员在正式流程确认。

### 10.6 基础数据与部署初始化

普通业务用户不需要执行系统初始化。全新部署由部署责任人按 `docs/系统部署手册.md` 操作，基础数据的内容和口径见 `docs/基础数据与初始化清单.md`；系统管理员可在顶部栏帮助中搜索“基础数据”或“部署初始化”查看角色化指南。

1. 先准备 Node.js、MySQL 8、企业 OIDC、HTTPS 反向代理和受控环境配置，再执行数据库迁移并检查迁移状态。
2. 只在**空业务库**执行一次 `npm run db:init`。正式基线包含 28 间会议室（18 间开放、10 间待核验）、主楼和南配楼共 24 层 427 个总部 3D 空间、7 个角色、3 个初始内部成员、7 个部门、默认预约规则、审批流程与动态规则、13 类会务目录和默认责任区。
3. 核心集合与总部 3D 在同一 MySQL 事务写入。任一核心业务集合或总部 3D 相关表已有数据都会拒绝，重复执行同样拒绝；不得为了重跑而清空业务库。
4. 初始化后核对资源、待核验容量、成员、部门和角色，再绑定首个企业 OIDC 管理员、构建并启动服务，按部署手册完成健康检查和业务冒烟。
5. 初始内部成员不是可直接登录的生产账号；10 间 `PENDING` 会议室的容量是待核验技术占位。办公室类空间中的开放办公区不是逐工位台账，“已分配”也不代表现场实测有人。
6. 初始化 JSON 仅是首次输入，运行后以 MySQL 为准。已有业务库升级只执行备份、新增迁移、构建和应用发布，**不得执行 `db:init`、演示 `db:seed`，也不得把 `db:seed:hq3d` 当作通用升级命令**。

助手只提供上述指南和页面导航，不直接执行部署、迁移、初始化、seed、备份恢复或身份绑定，也不会把指南展示当作操作已完成。

### 12.4 安全边界

- 新建、修改、续期不会由助手直接落库。
- 取消、审批、签到和完成工单需要点击确认，并由服务端再次检查。
- 助手不直接执行保密授权、组织同步应用、集成补偿/重放、设备撤销/重启、部署、数据库迁移、正式或演示初始化、身份绑定或备份恢复。
- 总部 3D 工具只读查询，不上传、识别、预检或导入布局，也不修改房间资料、维护记录或资源映射；这些操作仍须在正式页面按权限完成。
- 对话、草案和 3D 定位卡片保存在当前用户的 MySQL 会话中，刷新可恢复，但不会自动执行。
- 助手统计不是正式运营报表的替代品。

## 13. 常见问题

操作失败时，页面统一显示中文原因或处理建议。英文业务错误码只保留在接口、日志、审计和技术联调中，不要求普通用户根据错误码排障；失败操作未确认成功前，不要把旧数据当成最新结果。

| 提示或现象 | 处理方式 |
|---|---|
| 无法找到可订会议室 | 检查时间、人数、设备、开放时段、资源状态和部门额度；不要选择 PENDING 或维护资源 |
| 提交时提示冲突 | 重新查询最新空档；打开表单时的空档不代表提交时仍可用 |
| 提示联系人信息不完整 | 请管理员补全本人姓名、座机和手机档案 |
| 提示申请人信息不存在或已失效 | 联系管理员核对成员档案，不要反复提交相同申请 |
| 其他操作失败 | 按页面中文提示修正输入、刷新或重新登录；仍失败时记录操作时间、页面和中文提示，由管理员结合请求 ID、日志和审计排查 |
| 涉密会议无法提交 | 核对会议类型/涉密选择，并确认申请人和全部参会人在白名单内 |
| 找不到某功能 | 打开帮助搜索；若当前角色无权，联系管理员确认职责 |
| 助手找到同名参会人 | 按候选信息进一步区分，不要让系统静默选择 |
| 助手已生成草案但列表没有预约 | 打开正式表单核对并提交；草案本身不是预约 |
| 修改后收到旧时间提醒 | 保留请求和预约信息联系管理员；系统按排期版本使旧任务失效，需核查具体通知事实 |
| 报表和对话统计不同 | 以正式运营报表的筛选和对账口径为准 |
| 监控页面提示连接中断 | 普通网络断连会保留最近快照并自动重连；检查网络，会话失效时重新登录。若提示权限已变更，旧数据已清除且不会自动恢复，请联系管理员核对对应监控授权；不要把旧快照当成当前事实 |
| 办公室显示已分配但现场无人 | 已分配是总部3D房间资料台账，不是门禁或传感器实测；如需变更由授权人员在总部3D维护 |
