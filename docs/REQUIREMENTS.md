# 智慧办公空间管理系统 (SmartOffice) - 需求说明书

## 1. 引言

### 1.1 编写目的
本文档旨在明确"智慧办公空间管理系统"的功能需求、业务逻辑及非功能性要求，为后续的设计与开发提供基准。

### 1.2 项目背景
随着现代化办公节奏的加快，企业对会议室和工位等物理资源的利用效率要求日益增高。本项目旨在通过数字化手段实现资源的一键预约、自动化审批及智能化分配。

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| RBAC | 基于角色的访问控制 (Role-Based Access Control) |
| Realtime | 实时数据推送功能 |
| 周期性预约 | 按天/周/月重复创建的预约 |
| 审批流 | 多级审批节点组成的审批流程 |

---

## 2. 角色定义

系统采用基于角色的访问控制（RBAC），预设四类核心角色：

| 角色 | 标识 | 说明 | 权限范围 |
|------|------|------|----------|
| **系统管理员** | SYSTEM_ADMIN | 系统维护者，拥有最高管理权 | 全部权限 |
| **审批负责人** | APPROVAL_ADMIN | 业务审核者，负责资源申请的审批 | 审批中心、预订管理、个人中心 |
| **会议服务** | MEETING_SERVICE | 会议室服务管理人员 | 会议室管理、预订查看、个人中心 |
| **普通员工** | EMPLOYEE | 资源的使用者 | 资源查看、预订、个人中心 |

### 2.1 权限清单

```typescript
// 基础视图权限

// 管理权限
```

## 3. 功能需求

### 3.1 空间资源管理

#### 3.1.1 资源分类
- 支持 **会议室 (ROOM)** 与 **工位 (DESK)** 两大类资源
- 每类资源可配置独立属性

#### 3.1.2 属性维护
| 属性 | 类型 | 说明 |
|------|------|------|
| 名称 | 文本 | 资源名称，如"会议室 A" |
| 容量 | 整数 | 可容纳人数 |
| 位置 | 文本 | 物理位置，如"3楼东侧" |
| 设施 | 数组 | 配套设施（投影仪、白板、视频会议等） |
| 状态 | 枚举 | 可用、占用、维护中 |

#### 3.1.3 状态监控
- 实时展示资源状态
- 支持手动设置维护状态

### 3.2 预约申请体系

#### 3.2.1 单次预约
- 选择特定日期与时间段
- 选择资源类型和具体资源
- 填写参会人数和会议用途
- 实时冲突检测

#### 3.2.2 周期性重复预约
- **重复频率**: 按"天"、"周"、"月"
- **重复次数**: 最多 10 次
- **批量生成**: 系统自动创建多个预约申请
- **独立审批**: 每个生成的预约独立进行审批流程

#### 3.2.3 冲突预警
- 实时检测时间段冲突
- 冲突时提供基于 AI 的"建议时段"
- 显示冲突的已有预订详情

#### 3.2.4 附加服务
| 服务 | 说明 |
|------|------|
| 领导参会 | 标记是否有领导参加，填写领导信息 |
| 视频会议 | 是否需要视频会议设备 |
| 茶水服务 | 是否需要茶水服务 |
| 桌牌服务 | 是否需要桌牌及桌牌内容 |

### 3.3 自动化审批链路

#### 3.3.1 自定义引擎
- 管理员可自由编排多级审批节点
- 支持增删改审批节点
- 节点顺序可调整

#### 3.3.2 角色关联
- 每个审批节点关联特定权限角色
- 该角色的所有用户均可审批

#### 3.3.3 审批流程
1. 用户提交预约申请
2. 系统根据审批流创建审批任务
3. 当前节点审批人收到通知
4. 审批人通过或拒绝
5. 通过则进入下一节点，拒绝则结束流程
6. 最后一个节点通过后，预约状态变为"已确认"

#### 3.3.4 审批历史
- 记录每个节点的审批结果
- 包含审批人、时间、意见
- 不可篡改的审计记录

### 3.4 智能 AI 辅助

#### 3.4.1 选址建议
- 基于 Gemini Flash 模型
- 根据会议目的、人数、所需设施推荐资源
- 多维度评分：容量匹配、设施匹配、历史偏好、可用性

#### 3.4.2 排期优化
- 在预约冲突时自动计算推荐时段
- 考虑会议室的空闲情况和用户偏好

#### 3.4.3 推荐算法权重
| 维度 | 权重 | 说明 |
|------|------|------|
| 容量匹配 | 30% | 会议室容量与参会人数匹配度 |
| 设施匹配 | 25% | 所需设施的满足程度 |
| 历史偏好 | 25% | 用户历史预订该会议室的比例 |
| 可用性 | 20% | 该时段会议室的空闲程度 |

### 3.5 会议室监控大屏

#### 3.5.1 实时数据
- 通过 Supabase Realtime 实时推送
- 30秒轮询作为备选方案
- 连接状态可视化

#### 3.5.2 统计卡片
- 今日预订会议数
- 今日预订总时长
- 正在进行会议数
- 本周预订总数

#### 3.5.3 时间格视图
- 横轴：7:00-21:00 时间段
- 纵轴：各会议室
- 色块表示预订时段
- 状态颜色区分

#### 3.5.4 今日预订列表
- 展示今日所有预订详情
- 支持搜索、筛选、排序
- 分页显示
- 可展开查看详细信息

#### 3.5.5 周视图
- 展示未来7天每天的预订概览
- 每天显示最多3个预订
- 点击可查看更多

#### 3.5.6 状态颜色
| 状态 | 颜色 | 说明 |
|------|------|------|
| 进行中(已批准) | 绿色深色 | 会议正在进行 |
| 即将开始(已批准) | 绿色浅色 | 会议将在近期开始 |
| 进行中(待审批) | 黄色深色 | 待审批的进行中会议 |
| 即将开始(待审批) | 黄色浅色 | 待审批的即将开始会议 |
| 已结束 | 灰色 | 会议已结束 |
| 空闲 | 深灰色 | 无预订 |

### 3.6 组织与数据管理

#### 3.6.1 层级架构
- 无限层级的部门树形结构
- 支持部门增删改查
- 支持部门的合并与迁移

#### 3.6.2 用户管理
- 用户信息的增删改查
- 角色分配
- 部门关联
- 批量导入（CSV/JSON）

#### 3.6.3 批量操作
- CSV 格式导入成员
- CSV 格式导入资源
- CSV 格式导入部门
- 自动识别父子关系

#### 3.6.4 备份恢复
- 全量业务数据导出（JSON 格式）
- 一键恢复功能
- 包含用户、资源、预订、角色、部门、工作流

## 4. 非功能性需求

### 4.1 用户体验
- **响应式布局**: 适配桌面、平板、手机
- **主题切换**: 提供 5 套商务配色方案
- **加载优化**: 秒级数据加载
- **离线支持**: 离线模式下可查看缓存数据

### 4.2 性能要求
- 页面首屏加载 < 2s
- 数据查询响应 < 500ms
- 实时推送延迟 < 1s
- 支持 100+ 并发用户

### 4.3 可靠性
- 数据持久化存储（Supabase）
- 本地缓存（LocalStorage）
- 断线重连机制
- 数据备份与恢复

### 4.4 安全性
- 密码 SHA-256 加密存储
- 基于 JWT 的会话管理
- Row Level Security (RLS)
- 操作审计日志

### 4.5 兼容性
- 支持 Chrome、Firefox、Safari、Edge 最新版本
- 支持移动端浏览器
- 响应式断点：sm(640px)、md(768px)、lg(1024px)、xl(1280px)

## 5. 接口需求

### 5.1 外部服务
- **Supabase**: PostgreSQL 数据库 + Realtime 实时推送
- **Gemini API**: AI 推荐服务（可选）

### 5.2 环境变量
```env
VITE_SUPABASE_URL       - Supabase 项目 URL
VITE_SUPABASE_ANON_KEY  - Supabase 匿名密钥
VITE_GEMINI_API_KEY     - Gemini API 密钥（可选）
```

## 6. 附录

所有数据库表使用 `smartoffice_` 前缀：
- `smartoffice_users`
- `smartoffice_resources`
- `smartoffice_bookings`
- `smartoffice_roles`
- `smartoffice_departments`
- `smartoffice_workflow`

### 6.2 预约状态流转
```
PENDING(待审批) → APPROVED(已确认)
                → REJECTED(已拒绝)
                → CANCELLED(已取消)

APPROVED → COMPLETED(已完成) [自动或手动]
```
